# Чек-лист ручной проверки релиза 2.5.2

Проверка выполняется на Windows 10 или 11 x64 до публикации релиза. Отдельные пункты проверяются на реальном Mac с macOS 10.15 или новее. Используйте копию рабочего журнала и отдельную учётную запись, если это возможно. После каждого опасного действия сохраняйте резервную копию.

Подготовка:

- [ ] Установлена версия 2.3.0 из GitHub Releases.
- [ ] Создан и отправлен тег `v2.5.2` (`git tag v2.5.2 && git push origin v2.5.2`).
- [ ] Завершён workflow **Build Tauri app**, скачан артефакт `TradeJournal-<sha>` с Windows-машины.
- [ ] Завершён workflow **Build macOS app**, скачан артефакт `TradeJournal-macos-<sha>` с универсальным DMG.
- [ ] Открыт черновик релиза `v2.5.2` в GitHub (появляется после успешной сборки); проверены все вложения: установщик `TradeJournal_2.5.2_x64-setup.exe`, подпись `.sig`, портативный ZIP, `latest.json`, `SHA256SUMS.txt`.
- [ ] Пока черновик не опубликован кнопкой **Publish**, автообновление версий 2.3.0 на 2.5.2 не затрагивается.
- [ ] После публикации проверено, что в 2.3.0 работает поиск обновлений, скачивание и установка.
- [ ] Есть журнал, созданный версией 2.3.0, с несколькими счетами, сделками, частичными выходами, скриншотами и записями.
- [ ] Есть резервная копия исходного журнала и папки `%APPDATA%\TradeJournal`.
- [ ] Подготовлены JSON, CSV и ZIP-экспорт из версии 2.3.0.
- [ ] Проверка выполняется на сборке 2.5.2, собранной из тега `v2.5.2`.

## 0. Мерцание интерфейса

- [ ] При прокрутке длинного списка сделок, журнала и аналитики шапка не мерцает и не дёргает страницу.
- [ ] Переключение между разделами происходит без вспышки и без пустого экрана.
- [ ] После переключения раздел виден сразу, без анимации появления.
- [ ] При прокрутке вниз и переключении раздела страница сразу открывается сверху.
- [ ] Те же проверки выполнены в веб-версии и в Windows-приложении (WebView2).

## 1. Открытие журнала версии 2.3.0

- [ ] После запуска 2.5.2 журнал открывается без ошибок и предложения начать с нуля.
- [ ] На месте все счета, сделки, записи, теги, настройки, часовой пояс и торговые сессии.
- [ ] Пользовательские сессии из старой версии сохранили названия и время начала, сделки распределены по ним.
- [ ] Частично закрытые сделки отображаются как «Частично закрыта»; остаток позиции и реализованный P&L корректны.
- [ ] Комиссии частично закрытых сделок пересчитаны по новой логике: на закрытый объём, а не на всю сделку. Суммы совпадают с ожидаемым расчётом.
- [ ] Автоматическая резервная копия существует в `%APPDATA%\TradeJournal\backups`.
- [ ] Файл `journal.previous.json` создан или обновлён после первого сохранения.
- [ ] Скриншоты открываются из журнала и из карточки сделки.

## 2. Календарь и кривая капитала

- [ ] Создайте сделку с входом в понедельник и полным выходом в среду.
- [ ] В календаре результат появился в среду, а не в понедельник.
- [ ] Кривая капитала и дневной P&L учитывают дату выхода.
- [ ] Сделка с несколькими частичными выходами распределена по датам этих выходов.
- [ ] Дневные лимиты и статистика дня считаются по датам выходов.
- [ ] В панели дня отображаются результат дня и PnL каждой сделки, включая сделки, открытые и закрытые в один день, и частично закрытые сделки.
- [ ] Подпись под результатом дня показывает число сделок с результатом и соотношение прибыльных и убыточных, а не «закрытых сделок нет».

## 3. Экспорт и импорт

- [ ] **Экспорт JSON** открывает диалог сохранения, файл создаётся и открывается как корректный JSON.
- [ ] **Экспорт CSV** открывает диалог сохранения, файл открывается в Excel или другом редакторе, строки и разделители корректны.
- [ ] **Экспорт ZIP** открывает диалог сохранения, архив открывается, внутри есть `journal.json`, `README.txt` и скриншоты.
- [ ] **Импорт JSON** из экспорта 2.3.0 проходит, сделки и записи не теряются, скриншоты отображаются.
- [ ] **Импорт ZIP со скриншотами**: в веб-браузере и в Windows-приложении выберите ZIP-файл через «Импорт JSON / ZIP». Приложение само извлекает `journal.json`, показывает предпросмотр, а после подтверждения восстанавливает сделки, записи и скриншоты.
- [ ] **Импорт ZIP на Windows**: проверьте, что ZIP c методом Deflate и stored открывается одинаково; повреждённый архив и архив без `journal.json` показывают понятную ошибку и не заменяют журнал.
- [ ] Импорт CSV с частичными выходами проходит без ошибок; дубликаты и битые строки обрабатываются как раньше.
- [ ] После импорта проверьте отмену действия кнопкой в уведомлении, если она доступна.

## 4. Резервные копии и восстановление

- [ ] **Настройки → Приложение и локальные файлы → Создать резервную копию** создаёт файл в `backups`.
- [ ] Восстановление из созданной копии проходит; данные совпадают с состоянием до изменения.
- [ ] Восстановление из более старой копии не повреждает журнал и скриншоты.
- [ ] Повреждение `journal.json` (на копии данных) показывает экран восстановления, а не перезаписывает файл.
- [ ] Кнопка **«Вернуть предыдущую версию»** на экране восстановления возвращает `journal.previous.json` и перезапускает приложение.
- [ ] После восстановления приложение запускается, журнал открывается, скриншоты на месте.

## 5. Скриншоты

- [ ] Добавьте скриншот через выбор файла, вставку из буфера (`Ctrl+V`) и drag-and-drop.
- [ ] Миниатюра появляется в строке сделки, изображение открывается на весь экран.
- [ ] Удаление скриншота из сделки работает; после сохранения журнал не ссылается на удалённый файл.
- [ ] Замените скриншот другой картинкой и проверьте, что отображается новая.
- [ ] **Настройки → Здоровье хранилища → Проверить** находит неиспользуемые файлы.
- [ ] Очистка неиспользуемых скриншотов удаляет только файлы без ссылок; журнал, предыдущая версия и резервные копии не затронуты.
- [ ] После очистки откройте несколько сделок со скриншотами — изображения на месте.

## 6. Второй экземпляр приложения

- [ ] Запустите TradeJournal повторно, пока первый экземпляр открыт.
- [ ] Второй процесс не создаётся; активируется существующее окно.
- [ ] Журнал не открывается в двух окнах и не возникает конфликт сохранения.

## 7. Автообновление с 2.3.0 на 2.5.2

- [ ] Установите 2.3.0 и убедитесь, что в настройках отображается версия `v2.3.0`.
- [ ] Опубликуйте релиз `v2.5.2` с `latest.json`, установщиком и подписью `.sig`.
- [ ] В 2.3.0 откройте **Настройки → Приложение и локальные файлы → Проверить обновления**.
- [ ] Приложение находит 2.5.2 и показывает кнопку скачивания и установки.
- [ ] Скачивание проходит, подпись проверяется, установщик запускается.
- [ ] После перезапуска отображается версия `v2.5.2`, журнал и скриншоты сохранены.
- [ ] Повторная проверка обновлений сообщает, что установлена актуальная версия.

## 8. Установщик и удаление

- [ ] Установщик `TradeJournal_2.5.2_x64-setup.exe` запускается без прав администратора.
- [ ] Установка выполняется для текущего пользователя в стандартную папку.
- [ ] Язык интерфейса установщика корректный (русский), названия пунктов понятны.
- [ ] После установки приложение запускается, ярлык и запись в списке программ присутствуют.
- [ ] Портативный ZIP запускается без установки и использует те же данные из `%APPDATA%\TradeJournal`.
- [ ] Удаление через **Параметры Windows → Приложения** удаляет программу.
- [ ] После удаления папка `%APPDATA%\TradeJournal` с журналом, скриншотами и резервными копиями сохраняется.

## 9. Язык и оформление

- [ ] **Настройки → Интерфейс**: переключение на английский перезагружает интерфейс, все подписи, меню, кнопки и сообщения становятся английскими.
- [ ] Заметки, сделки, названия счетов, инструменты и сетапы остаются точно в том виде, в каком были введены.
- [ ] Переключение обратно на русский возвращает русские подписи; выбор сохраняется после перезапуска.
- [ ] Светлая тема применяется ко всем разделам, графикам и календарю; тёмная тема возвращается без артефактов.
- [ ] Пресеты акцента и свой акцентный цвет меняют кнопки и выделения, но прибыль и убыток остаются зелёным и красным.
- [ ] Готовые шаблоны применяют тему, акцент, фон и панели одним кликом; выбранный шаблон подсвечен.
- [ ] После ручного изменения любого цвета подсветка шаблона снимается, выбранные цвета сохраняются.
- [ ] Свои цвета фона и панелей применяются, текст остаётся читаемым.
- [ ] Карточки статистики счёта, карточки аналитики, подсказки графиков и записи журнала используют фон выбранной темы или шаблона.
- [ ] В светлой теме предупреждение о дневном лимите, значения лимитов, подписи графиков и бейджи читаемы.
- [ ] **Сбросить оформление** возвращает тему и цвета по умолчанию, не меняя выбранный язык.
- [ ] После перезапуска приложения язык и оформление сохраняются, журнал, скриншоты и резервные копии не затронуты.
- [ ] Те же проверки выполнены в веб-версии.

## 10. Торговые сессии и часовые пояса

- [ ] В журнале сделок есть колонка «Сессия»; клик по заголовку сортирует сделки по сессии, повторный клик меняет направление.
- [ ] Порядок сессий при сортировке соответствует времени начала сессии; сделки без времени остаются в конце.
- [ ] В **Настройки → Границы торговых сессий** кнопка **Добавить сессию** добавляет строку, а кнопка удаления убирает её.
- [ ] Нельзя удалить последнюю оставшуюся сессию — кнопка удаления у неё неактивна.
- [ ] После добавления, переименования и удаления сессий нажмите **Сохранить**: изменения применяются к журналу и сохраняются после перезапуска.
- [ ] При одинаковых названиях или одинаковом времени начала сессий показывается понятная ошибка, настройки не сохраняются.
- [ ] Названия своих сессий остаются в исходном виде при переключении на английский язык.
- [ ] Поле **Часовой пояс** содержит группы «Популярные» и «Все часовые пояса»; у каждого пояса показано текущее смещение от UTC.
- [ ] При смене часового пояса время сделок и текущая сессия пересчитываются; сохранённый пояс, которого нет в списке IANA, остаётся доступным.
- [ ] Блок **Текущая сессия** показывает актуальную сессию и время, обновляется при изменении пояса и границ сессий и раз в 30 секунд.
- [ ] Те же проверки выполнены в веб-версии и в Windows-приложении.

## 11. macOS-сборка

Проверка выполняется на реальном Mac другом или сопровождающим; сборка не подписана и не нотаризована.

- [ ] Workflow **Build macOS app** завершился успешно; скачан артефакт `TradeJournal-macos-<sha>`.
- [ ] В артефакте есть `TradeJournal_2.5.2_universal.dmg` и `SHA256SUMS.txt`; контрольная сумма DMG совпадает.
- [ ] DMG открывается, приложение перетаскивается в **Applications**.
- [ ] При первом запуске Gatekeeper показывает предупреждение, а **Системные настройки → Конфиденциальность и безопасность → Всё равно открыть** запускает приложение.
- [ ] Альтернативно `xattr -cr /Applications/TradeJournal.app` снимает карантин, после чего приложение запускается.
- [ ] Приложение работает на Apple Silicon; при возможности проверено и на Intel Mac.
- [ ] На главной странице и в настройках отображается бейдж **macOS**.
- [ ] Журнал создаётся в `~/Library/Application Support/TradeJournal`; кнопка **Открыть папку данных** открывает Finder.
- [ ] Создание резервной копии, восстановление, импорт JSON/ZIP и скриншоты работают.
- [ ] **Проверить обновления** сообщает, что на macOS обновления устанавливаются вручную, и не пытается запустить установщик Windows.
- [ ] Переключение языка и оформления работает так же, как в Windows-версии.
- [ ] Приложение корректно закрывается и запускается повторно; журнал сохраняется.
